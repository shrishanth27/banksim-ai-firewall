Problem Statement

The Vulnerability of Financial AI Assistants

Generative AI is revolutionizing conversational banking, but probabilistic models are inherently vulnerable to prompt hijacking and indirect injection.

Direct Prompt Injections

Adversaries use roleplay jailbreaks ("DAN mode", "System Diagnostic Mode") to force the model to disregard bank authorization limits.

Hostile Transaction Memos

Secondary input channels (like transaction descriptions or payee references) carry obfuscated exploits, XSS payloads, or SQL injection strings.

The Lethal Flaw: AI Agency

Granting an LLM direct API execution rights means a single compromised instruction can initiate unauthorized wires and balance tampering.

Solution Overview

BankSim: Zero-Agency Advisory AI Firewall

We separate untrusted AI evaluation from trusted financial state mutation through a rigorous zero-trust architecture.

Advisory-Only Paradigm

The AI model never holds banking execution privileges or database access. It outputs strict JSON classification and risk scores (0–100).

Multi-Tier Defense Pipeline

Deterministic regex heuristics filter known attack signatures in <15ms, followed by semantic LLM threat analysis with strict XML delimiters.

Cryptographic 2-Step Confirmation

Approved transfers require single-use, 5-minute confirmation tokens. Financial balances can only be updated by backend-verified human confirmation.

Prompt Methodology

Treating Inputs as Untrusted Data, Not Instructions

Defensive prompt engineering in prompts/system-prompt.txt prevents instruction hijacking.

XML Boundary Isolation

User requests and memos are strictly enclosed within <untrusted_user_request> and <untrusted_transaction_memo> tags.

Strict JSON Schema Mandate

The model is instructed to output ONLY valid JSON containing status, risk_score, threat_category, intent, and explanation—no markdown fences, no conversational preamble.

Server-Side Schema Verification

The backend validates the model's response structure. If parsing fails or fields are missing, the system automatically fails closed.

Security & Edge Cases

Edge Case Hardening & Invariant Protections

Built-in safeguards against parameter tampering, evasion, and system failures.

Ambiguity Detection

Detects vague financial requests ("send some money to Bob") and blocks them immediately before any ledger interaction.

Obfuscation Defense

Decodes base64 strings (e.g., encoded instruction payloads) and flags leetspeak evasion attempts (e.g., "1gn0r3", "0v3rr1d3").

Single-Use Token Enforcement

Prevents replay attacks. Once a confirmation token is consumed or expires (5 mins), subsequent attempts are rejected by trusted backend code.
